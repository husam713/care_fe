# 16 — خطة التعريب إلى العربية (Arabic + RTL)

> **الهدف المعلن:** استخدام CARE بالعربية، ثم تطوير ميزات. هذه الوثيقة مبنية على قياسات فعلية من `care_fe` @96d7e93 و`husam713/care` @67a4618. الأرقام الجهدية نسبية (S/M/L)، وليست تقديراً زمنياً مُتحقَّقاً.

## 2. حجم عمل RTL في الواجهة (قياس آلي)
عدد الاستخدامات (مطابقات نمط) لخصائص CSS الفيزيائية (يمين/يسار) في `src/`:

| النمط | ملفات | مطابقات |
|---|---:|---:|
| `ml-*` / `mr-*` | 284 | 657 |
| `pl-*` / `pr-*` | 157 | 247 |
| `left-*` / `right-*` | 121 | 205 |
| `text-left` / `text-right` | 82 | 251 |
| `border-l` / `border-r` | 67 | 177 |
| `rounded-l/r/tl/tr/bl/br` | 44 | 105 |
| `space-x-*` | 74 | 110 |
| `translate-x-*` | 16 | 25 |
| `rotate-180` | 10 | 11 |
| **المجموع التقريبي** | | **≈ 1,800** |

- **مكوّنات `components/ui` (92 ملفاً):** ≈ 172 استخداماً. توجيهات المشروع تقول «لا تعدّل `components/ui` مباشرة»؛ التعريب يتطلب استثناءً مُوثَّقاً لهذا المجلد.
- **أيقونات اتجاهية:** 80 ملفاً تستخدم `Chevron/Arrow Left/Right` ⇒ تحتاج انعكاساً (`rtl:rotate-180`) حيث تدل على التنقل لا على الزمن.
- **الأدوات:** Tailwind v4 يدعم الخصائص المنطقية (`ms-/me-/ps-/pe-/start-/end-/text-start/border-s/rounded-s`) والمتغير `rtl:`. الاستخدام الحالي لها شبه معدوم (`start/end` ≈ 32 مطابقة).
- **تحويل شبه آلي:** معظم المطابقات قابلة لـ codemod (`ml-4 → ms-4`، `text-left → text-start`...)؛ ما يحتاج قراراً بشرياً: `space-x` (→ `gap` أو `rtl:space-x-reverse`)، `translate-x`، المواضع المطلقة، والرسوم (recharts وreactflow).

## 4. المخاطر
1. **تباعد الـ fork عن upstream:** codemod RTL يلمس مئات الملفات ⇒ تعارضات دائمة عند المزامنة مع `ohcnetwork/care_fe` (المشروع نشط جداً). **التخفيف:** (أ) كتابة codemod كسكربت يُعاد تشغيله بعد كل مزامنة، أو (ب) المساهمة في upstream بدعم RTL للاستفادة من الصيانة المجتمعية — أنصح بالتحقق أولاً من وجود عمل سابق هناك.
2. **السلامة السريرية:** الأرقام والجرعات والوحدات في نص ثنائي الاتجاه قد تُعرض مقلوبة أو مبهمة؛ يجب اختبار حالات الجرعات والمقاطع الرقمية بعناية، وعدم الاعتماد على ترجمة آلية للمصطلحات الدوائية.
3. **الترجمة الآلية** للمصطلحات الطبية: تحتاج مراجعة طبيب/صيدلي ناطق بالعربية قبل الاستخدام السريري.
4. **`components/ui` المحظور تعديله:** يلزم قرار صريح لتخصيصه أو إيجاد طبقة تغليف.
5. **المكتبات الخارجية:** recharts وreactflow وreact-day-picker وpigeon-maps ومحرر MDX ومحرر Lexical لها سلوك RTL متفاوت (لم يُختبر).
6. **أداء/حجم:** ملف ترجمة إضافي ≈ 170 ألف حرف + خط عربي.

## 6. تسلسل مقترح
1. **مرحلة 0 (إثبات جدوى، S):** AR-1 + AR-2 + ملف `ar.json` تجريبي لشاشة الدخول والـ Dashboard (≈ 100 مفتاح) + RTL لهذه الشاشتين فقط ⇒ صور تؤكد الاتجاه والخط.
2. **مرحلة 1 (تدفق الموظف الأساسي):** AR-4 (codemod) + AR-3 للشاشات الرئيسية (مريض، لقاء، مواعيد) + AR-5 + AR-6.
3. **مرحلة 2:** الباقي من الترجمة، AR-7، AR-8، AR-9.
4. **مرحلة 3:** المرضى والحجز العام، المحتوى السريري (AR-10).
بعد مرحلة 1 يكون النظام قابلاً للاستخدام بالعربية جزئياً (مع fallback إنجليزي)، ثم تبدأ الميزات الجديدة على أساس RTL مستقر.
